# Пинг и автоматический выбор сервера

Пинг от роутера до VPN-сервера показан рядом с текущим сервером, в выборе сервера и настройках автовыбора. Это ICMP до адреса сервера, отдельно от проверки HTTPS через VPN. Замеры настроенных кандидатов объединяются между списками и обновляются не чаще раза в минуту; показывается среднее до трёх последних успешных замеров. После двух минут значение считается устаревшим. Отсутствие ICMP-ответа не означает, что VPN не работает.

Для каждого списка можно выбрать «По меньшему пингу» или «По заданному порядку». В режиме пинга выбираются только серверы, прошедшие проверку VPN. Ручной выбор и расписание имеют приоритет; при их отказе резерв выбирается по пингу. Чтобы не переключать рабочие соединения при небольших колебаниях, улучшение должно составлять минимум 10 мс и 20%, а кандидат должен оставаться здоровым не меньше минуты или заданного времени восстановления. После переключения действует такой же период удержания. При отказе текущего VPN сохраняется существующий период подтверждения отказа, без дополнительного ожидания пинга.

Миграция SQLite добавляет `selection_mode` с совместимым значением `priority`. Старые API-клиенты при обновлении политики сохраняют её режим и привязку к списку. Настроенные домены и порядок серверов не переписываются.

Проверки: полный `go test -race ./...`, повтор automation race после исправления выбора резервов, `go vet ./...`, 31 frontend-тест, production-сборка, независимое ревью. В браузере с вымышленными данными проверены пинг, отсутствие ICMP-ответа, сохранение режима и `ruleId`, мобильная ширина 390 px без горизонтальной прокрутки.

На роутер установлена сборка исходников `9ee7bce`, резервная копия: `/mnt/usb-4d3e56cb/vpn-manager/backups/server-ping.HdHfAo`. Подтверждены реальные замеры: Sweden около 34–36 мс, Latvia около 41 мс, Netherlands/Germany около 61–62 мс. Для общего списка и DeepSeek включён `latency` через API. Сохранность остальных полей правил, политик и доменов подтверждена прежней контрольной суммой `59a2a5f37ac8a5dda871971e83143ad23de3885d89feb9a3c5cf81a54ee09003`; из сравнения исключён только новый `selectionMode`. Сохранены 5 правил, 155 записей и два независимых списка.

После периода стабилизации обе политики автоматически переключились с Germany на Sweden #4: около 33 мс ICMP против 64 мс до Germany. Статус подтвердил причину `healthy target selected by recent server ping`. Одинаковый выбранный сервер не объединяет их отдельные списки доменов.

Через физический Wi-Fi `en0` с DNS роутера проверены ya.ru (302), YouTube (200), ChatGPT (200) и DeepSeek API (401 без API-ключа). Бинарники sing-box/OpenVPN и основной WAN-маршрут не изменены.
