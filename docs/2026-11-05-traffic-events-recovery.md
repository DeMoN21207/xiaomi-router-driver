# Восстановление статистики трафика и журнала

На роутере профиль `minimal` отключал автоматический сбор сайтов. API и фильтр ошибок отвечали HTTP 200, но страница трафика не объясняла отсутствие новых данных. Ручной сбор восстановил счётчики; профиль переключён на `normal` со сбором раз в 120 секунд, остальные настройки маршрутизации сохранены.

Проверка VPN-статистики выявила ещё две причины: конфигурация DNS observer существовала без файла журнала, а сборщик строил классификатор по сохранённым правилам без общего списка и фактического автовыбора.

- DNS observer применяет изменения через ограниченный по времени restart dnsmasq; обычный reload/SIGHUP не перечитывает `log-queries`/`log-facility` ([официальное руководство](https://thekelleys.org.uk/dnsmasq/docs/dnsmasq-man.html)). Неизменённая конфигурация с существующим журналом не вызывает перезапуск. При ошибке восстанавливается предыдущий файл и выполняется попытка восстановления сервиса; следующая выборка повторяет активацию. Операции включения и отключения сериализованы.
- Сборщик сайтов и история трафика используют снимок маршрутов после общего списка, автовыбора и резервного провайдера. Чтение не ждёт сетевых проверок failover и не меняет сохранённые правила.
- API сообщает фактический настроенный интервал автосбора с учётом переменных окружения. Интерфейс различает частоту сбора и обновления экрана, показывает отключённый сбор и ошибки загрузки. Этот статус описывает настройку интервала, а не отдельную проверку здоровья сборщика.
- Журнал сохраняет правильный счётчик всех событий при фильтрации, удаляет ANSI-коды цветов при отображении и переносит длинные сообщения.

Регрессионные тесты воспроизвели отсутствие статуса сборщика, неприменение DNS-конфигурации, потерю общих маршрутов и блокировку чтения трафика во время failover. Проверены конфигурации minimal/normal/detailed и переопределения интервала, восстановление файла после ошибки, общий и отдельный маршруты, резервный провайдер и сохранность исходных правил.

Проверки: полный `go test -race ./...`, `go vet ./...`, 32 frontend-теста, production-сборка, браузерный стенд для отключённого/включённого сбора, ошибки API, фильтрации событий и сообщений без ANSI.
